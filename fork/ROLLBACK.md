# Откат обновлений форка

Каждое обновление форка на новый upstream или крупная правка оставляет здесь запись:
что было до неё и как вернуть прежнее состояние. Новые записи — сверху.

## 2026-10-11 — переход с upstream v26.9.9 на v26.10.10

### Что было до обновления

| Что | Состояние до | Где взять |
|---|---|---|
| `main` форка | `981423fe` (форк на v26.9.9, PR #4) | `git log 981423fe` |
| Ветка `claude/windows-vpn-stability-tunneling-xcs6nb` | `78248e5c` (TUN-правки для Windows, ещё на v26.9.9) | там же |
| Коммит обновления | `4ce667cd` «Rebase fork onto upstream v26.10.10»: родители `78248e5c` и тег `v26.10.10` | |
| Библиотеки для приложения | релиз `lib-from-v26.9.9` (коммит `f9305693`); Windows-приложение Horus поставляет свой `xray.dll` из `3a7d99ff` | Releases этого репозитория; `Horus/Platforms/Windows/bin/README.md` в Horus-Release |
| Docker-образ сервера | **не пересобирался** в рамках этого обновления | серверы работают на прежнем образе |

### Что меняется для работающей инфраструктуры

Слияние в `main` само ничего не разворачивает: `docker.yml` и `build-lib.yml` запускаются
только вручную (или по тегу `lib-v*`). Серверы продолжают работать на старом образе, пока
новый не собран и не выкачен. Клиенты получат новое ядро, только когда новые
`libxray.so` / `xray.dll` положат в приложение.

### Как откатить

**Код форка (`main`).** Не переписывать историю, а откатить слияние новым коммитом:

```bash
git checkout main && git pull
git revert -m 1 <коммит слияния PR в main>   # -m 1: оставить сторону main
git push origin main                           # или через PR, как обычно
```

После этого `main` по содержимому снова равен `981423fe`, а `fork/upstream.txt` снова
`v26.9.9`. `fork export --check` проходит: патчи и оверлей возвращаются вместе с деревом.
Если нужно вернуть только upstream, оставив TUN-правки ветки, откатывайте только
`4ce667cd`: `git revert -m 1 4ce667cd`.

**Библиотеки.** Новый релиз (`lib-from-v26.10.10`) ничего не заменяет: прежний
`lib-from-v26.9.9` остаётся на месте. Откат — взять файлы из прежнего релиза. Новый
релиз можно удалить на странице Releases, если он мешает.

**Windows-приложение Horus.** Пока оно не переведено на новое ядро, откатывать нечего.
Если перевели — вернуть прежний файл:

```bash
git checkout <коммит до замены> -- Horus/Platforms/Windows/bin/xray.dll
```

и строку с коммитом в `Horus/Platforms/Windows/bin/README.md`. Ядро пишет свою версию
в первой строке лога (`Xray 26.10.10 … 4ce667cd` против `Xray 26.9.9 … 3a7d99ff`), так
что по логу пользователя видно, какое у него.

**Серверы.** Если образ из нового `main` всё же собран и выкачен, выкатить обратно
предыдущий тег образа (тот, что работал до этого). Сам `docker.yml` тег `latest` не
ставит, если его об этом не попросить (`latest: false` по умолчанию).

### Что именно поменялось и где искать, если что-то пойдёт не так

- Hysteria: при остановке ядра его клиенты теперь удаляются из общего пула
  (upstream `c7dbfd5e`, перенесено в `transport/internet/hysteria/fork_pause.go`,
  метод `reap`). Раньше они оставались до таймаута QUIC.
- Windows TUN: новые шаги upstream при старте и остановке (сброс DNS-кэша, отключение
  регистрации адресов TUN в DNS, выключение weak host send на физическом интерфейсе на
  время работы TUN, пропуск DNS-сервера TUN для собственных запросов ядра). Всё это
  отменяется при остановке. Переиспользование адаптера по имени (upstream #6811) в форк
  **не** взято — причина в `proxy/tun/fork_open_windows.go`.
- TLS: по умолчанию теперь встроенный набор корневых сертификатов (Mozilla), а не
  системный (upstream `5af2e9c2`). Узлы с сертификатом от публичного CA это не
  затрагивает. Если какой-то узел использует частный CA, установленный в системе,
  клиенту нужен `"useSystemCA": true` в `tlsSettings` (или закрепление сертификата).
- `udpHop` в finalmask: интервал теперь не меньше 5 с, `sockopt` убран. Текущие
  конфиги API его не используют.
